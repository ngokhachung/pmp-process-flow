## Day 1 — Tue 11 Aug · Introduction + PMP exam rules

**Study:** Section 1 *Introduction* (4 lectures · 5m) + Section 2 *Introduction to the PMP Exam* (14 lectures · 1h04m)

### What you must understand

- **The end-to-end certification path:** meet eligibility → submit application → (possible **random audit**) → pay the fee → schedule → sit the exam → receive results.
- **Eligibility:** four-year degree + 36 months leading projects + 35 contact hours · OR high school/associate degree + 60 months + 35 contact hours. Experience must fall within the **last 8 years**.
- **Exam structure:** 180 questions, **170 scored** (10 unscored pretest items), **240 minutes**, **two 10-minute breaks**. Once a break ends you **cannot return to the previous section** — this is where people lose easy points.
- **Question types:** single-answer multiple choice, multiple response, **matching**, **hotspot / point-and-click**, fill-in-the-blank. ECO 2026 adds: **a case study at the front of the exam**, **graphic-based**, **enhanced matching**, **drop-down**.
- **Scoring:** no published pass percentage. Results are reported per domain in four bands: **Above Target / Target / Below Target / Needs Improvement**. The exam is adaptively weighted — don't try to compute "how many do I need right."
- **Maintaining the credential:** 60 PDUs every 3 years.
- **The instructor's "secret to passing":** the PMP tests *how PMI wants you to behave*, not what you can memorize. Write that down — Day 20 comes back to it.

## Day 2 — Wed 12 Aug · Project management terms

**Study:** Section 3 *Project Management Terms* (20 lectures · 1h56m)

### What you must understand

- **Project vs. operations:** a project has a start and an end and produces something *unique*; operations are repetitive and ongoing. A project **enables change**, moving the organization from a current state to a future state.
- **Value:** the reason the project exists. The "focus on value" principle drives a great many correct answers.
- **Project → Program → Portfolio:** a program is a group of related projects managed together for *synergistic benefits*; a portfolio is a collection of projects/programs aligned to *strategic objectives*, not necessarily related to one another.
- **Life cycle, phase, deliverable, phase gate.**
- **Governance:** the framework for decision-making, approval, and oversight. In PMBOK 8 this is the performance domain that spans all five process groups.
- **Stakeholder:** anyone who *affects or is affected by* the project. Not just whoever pays.
- **PMO — three types:** *supportive* (advisory, low control) · *controlling* (requires compliance, moderate control) · *directive* (directly manages projects, high control).
- **Organizational structures and PM authority** — memorize this table:

| Structure | PM authority | Who controls the budget |
|---|---|---|
| Functional | Little to none | Functional manager |
| Weak matrix | Low (coordinator role) | Functional manager |
| Balanced matrix | Moderate | Shared |
| Strong matrix | High | Project manager |
| Projectized | Nearly total | Project manager |

- **Constraints:** scope, schedule, cost, quality, resources, risk — move one and the others move.
- **Product management vs. project management.**
- **Risk vs. issue:** a risk **has not happened yet** (uncertainty) → risk register; an issue **has already happened** → issue log. Confusing these is the easiest point to lose.
- **Leadership vs. management:** management = processes, systems, transactions; leadership = people, vision, influence.
- **Leadership styles:** servant, transformational, transactional, laissez-faire, charismatic, interactional. PMI favors **servant leadership**.
- **AI in project management** — **new in ECO 2026**, don't skim it.

### Self-check

1. Which matrix type is your own company? What authority does a PM actually hold there?
2. "The server might fail next month" — risk or issue? "The server just failed" — which one?
3. How does a program differ from a portfolio? Give an example from your own company.
4. Which PMO type can cancel your project?

### Exam traps / ECO 2026 gaps

- Situational questions often open with "You are a project manager in a **functional** organization…" — that clause determines the answer (you must *negotiate* with the functional manager, not decide unilaterally).
- **AI:** the course covers it in one lecture. ECO 2026 weights it more heavily. Write down AI applications (estimating, risk forecasting, automated reporting) and **limitations** (data bias, privacy, and the fact that **accountability cannot be delegated to AI**).

## Day 3 — Thu 13 Aug · 6 Principles + Project approaches

**Study:** Section 4 *Project Management Principles* (8 lectures · 54m) + Section 5 *Project Approaches* (8 lectures · 1h12m)

### What you must understand

**The 6 PMBOK 8 principles, in three groups** *(this grouping is the one you derived yourself in your Stage 1 notes — keeping it because it's memorable)*:

| Group | Principles |
|---|---|
| **Value-driven** | Focus on value · Integrate sustainability |
| **Proactive** | Adopt a holistic view · Embed quality into processes and deliverables |
| **Ownership** | Be an accountable leader · Build an empowered culture |

For each principle, be able to answer: *what does it force the PM to do differently when there's a conflict?*

**Approaches:**

- **Predictive:** requirements clear up front, low change, **scope fixed** — time and cost vary.
- **Adaptive (agile):** requirements unclear, high change, **time and cost fixed** — scope varies. This is **"inverting the triangle."**
- **Iterative vs. incremental** — hold the images: *iterative* = painting the Mona Lisa, sketch the whole then refine; *incremental* = building with Lego, each piece usable on completion. Agile is usually **both**.
- **Hybrid:** mixed — e.g. infrastructure built predictively while the interface is built adaptively.
- **How to choose — based on:** clarity of requirements, rate of change, level of risk/uncertainty, delivery cadence the customer needs, organizational culture, regulatory constraints.
- **Focus areas:** initiating, planning, executing, monitoring & controlling, closing — the five columns of your matrix.

### What you must understand

**The 7 PMBOK 8 performance domains** = the 7 rows of your matrix:

| # | Domain | Processes |
|:--:|---|:--:|
| 1 | **Governance** | 9 — the only one spanning all five columns |
| 2 | Scope | 6 |
| 3 | Schedule | 3 |
| 4 | Finance | 4 |
| 5 | Stakeholders | 7 |
| 6 | Resources | 5 |
| 7 | Risk | 6 |

**Common ITTOs — this is the part that saves you dozens of hours.** Understand these thirteen and you never memorize 40 ITTO tables:

- **EEF** (Enterprise Environmental Factors): everything *outside* the project that influences it and that you **cannot control** — law, market, weather, corporate culture. Tied to the *holistic view* principle.
- **OPA** (Organizational Process Assets): assets *inside* your organization that you **must use** — processes, templates, policies, the **lessons learned repository**, historical data.
- **Project documents** vs. **project management plan** — distinguish them: the *plan* is how you will do the work (contains baselines; changing it requires change control); *documents* are living records (risk register, issue log, assumption log — updated continuously).
- **Expert judgment** — appears in nearly every process.
- **Data management:** data gathering (brainstorming, interviews, focus groups) · data analysis (root cause, variance, trend, alternatives) · data representation (charts, matrices).
- **Decision making:** voting (unanimity, majority, plurality), autocratic, multicriteria decision analysis.
- **Interpersonal and team skills:** conflict management, facilitation, negotiation, active listening.
- **Meetings.**
- **Change request** — generated almost everywhere, always flowing into **1.8 Assess and Implement Changes**. Remember that direction.
- **Reporting project progress** · **Updates** (to the plan / documents / OPAs).
- **"etc."** — PMBOK 8 puts "etc." on every ITTO, which means **tailoring**: you are not obligated to run all 40 processes.

## Day 5 — Sat 15 Aug · 40 processes (1/7): Initiating + Governance planning

**Processes: `1.1` `5.1` `1.2` `1.3`**

### What you must understand

**`1.1` Initiate Project or Phase** — the project's "birth certificate"
- **Inputs:** business documents (**business case**, **benefits management plan**), agreements (contracts), EEFs, OPAs
- **T&T:** expert judgment, data gathering, interpersonal and team skills, meetings, **responsibility assignment matrix**, **project canvas**
- **Outputs:** ⭐ **Project charter** + ⭐ **Assumption log**
- **What the charter does:** formally authorizes the PM, states high-level objectives, high-level requirements, preliminary budget, and success criteria. **Signed by the sponsor**, not the PM.
- **Assumption log:** things you *believe true but cannot prove* — every assumption is the seed of a risk.

**`5.1` Identify Stakeholders** → ⭐ **Stakeholder register**
- Classification tools: **power/interest grid**, power/influence grid, **salience model** (power–legitimacy–urgency)
- Performed **continuously**, not once. Double-headed arrow with 1.1.

**`1.2` Integrate and Align Project Plans** → ⭐ **Project management plan**
- Merges all subsidiary plans + the **three baselines** (scope, schedule, cost) into a single non-contradictory whole.
- This is the "glue" of governance.

**`1.3` Plan Sourcing Strategy — procurement is now embedded in governance**
- **Make-or-buy analysis**
- **Contract types — who carries the risk:**

| Type | Abbrev. | Who carries the most risk |
|---|---|---|
| Firm Fixed Price | FFP | **Seller** |
| Fixed Price Incentive Fee | FPIF | Seller (partially shared) |
| Fixed Price with Economic Price Adjustment | FPEPA | Shared (hedges long-term inflation) |
| Cost Plus Fixed Fee | CPFF | **Buyer** |
| Cost Plus Incentive Fee | CPIF | Buyer (partially shared) |
| Cost Plus Award Fee | CPAF | Buyer |
| Time & Material | T&M | Buyer (used when scope is unclear; short engagements) |

- **Procurement SOW**, **bid documents** (RFI = request for information · RFQ = request for quote · RFP = request for proposal), **source selection criteria**

### Self-check

1. What authority does the charter give the PM that they didn't have before? Who signs it?
2. Why are there **only two processes** in the Initiating column, and why are these the right two?
3. Scope isn't clear yet and you must start immediately — which contract type? Why not FFP?
4. How does the assumption log differ from the risk register?

### Exam traps / ECO 2026 gaps

- **FFP: the seller carries the risk. CPFF: the buyer carries the risk.** The exam loves to ask it in reverse ("which contract carries the most risk *for the buyer*").
- "What should the PM do first when assigned to a project?" → **read the charter / identify stakeholders**, not build a detailed plan.
- Reminder: PMBOK 8 has **no separate Procurement domain** — it lives inside Governance, mostly in Planning.

## Day 6 — Mon 17 Aug · 40 processes (2/7): Scope

**Processes: `2.1` `2.2` `2.3` `2.4`**

### What you must understand

**`2.1` Plan Scope Management** → scope management plan + **requirements management plan** (the "rules of the game": who may change scope, at what level, who approves)

**`2.2` Elicit and Analyze Requirements** → ⭐ **Requirements documentation** + ⭐ **Requirements Traceability Matrix (RTM)**
- Elicitation techniques: interviews, focus groups, **facilitated workshops (JAD, QFD)**, brainstorming, **nominal group technique**, mind mapping, **affinity diagrams**, questionnaires, benchmarking, **prototypes**, observation/**job shadowing**, document analysis
- The **RTM** traces each requirement from its origin → deliverable → test. It is your weapon against scope creep.

**`2.3` Define Scope** → ⭐ **Project scope statement**
- Contains: product scope description, deliverables, **acceptance criteria**, **exclusions** (what you will NOT do — this section saves you in disputes), assumptions, constraints
- **Product scope** (features of the product) ≠ **project scope** (the work required to deliver it)

**`2.4` Develop Scope Structure** → ⭐ **WBS** + ⭐ **WBS dictionary**
- **Decomposition** down to the **work package** — small enough to estimate and assign
- **Control account** (performance measurement point) · **planning package** (not yet decomposed)
- **The 100% rule:** the WBS contains **all** the work — no more, no less
- The WBS is written in **nouns / deliverables**, not activities
- ⭐ **Scope baseline = scope statement + WBS + WBS dictionary** (memorize)

**Agile equivalents:** product backlog · epic → feature → user story · progressive elaboration in place of a fixed WBS

### Self-check

1. How many components in the scope baseline? Name them.
2. "The application must load a page in under 2 seconds" — product scope or project scope?
3. How far down do you decompose a WBS before stopping?
4. A customer asks for one small extra feature mid-project — which document proves it's out of scope?

### Exam traps / ECO 2026 gaps

- **Validate Scope (2.6)** = the customer **formally accepts** ≠ **Control Quality** = internal quality inspection. Order: **QC first → Validate Scope second**.
- **Scope creep** (uncontrolled scope growth) vs. **gold plating** (the PM or team **voluntarily** adding what the customer never asked for). **Both are wrong** — gold plating is wrong even when it's free.
- Agile items: no rigid WBS → the correct answer is usually "add it to the backlog and let the PO prioritize."

## Day 7 — Tue 18 Aug · 40 processes (3/7): Schedule + Resource planning

**Processes: `3.1` `3.2` `6.1` `6.2`**
*(Schedule is paired with resource estimating because they're inseparable — resource leveling sits at the junction.)*

### What you must understand

**`3.1` Plan Schedule Management** → schedule management plan (units of measure, acceptable variance thresholds, update rules)

**`3.2` Develop Schedule → ⭐ Schedule baseline** — technically the largest process:

- **Activity definition and sequencing — PDM:** **FS** (finish-to-start, most common), SS, FF, SF (rare)
- **Lead** (start earlier, overlap) vs. **lag** (imposed waiting time)
- **Duration estimating:** analogous (fast, least accurate, uses historical data) · parametric (unit rate × quantity) · bottom-up (most accurate, most effort) · **three-point**
- ⭐ **PERT (beta):** `(O + 4M + P) / 6` · **Triangular:** `(O + M + P) / 3` · **Standard deviation:** `(P − O) / 6`
- ⭐ **Critical path** = the **longest** path through the network = the shortest possible project duration. **Float = 0.**
- ⭐ **Total float = LS − ES = LF − EF** (how long an activity can slip without delaying the project finish)
- **Free float** = how long it can slip without delaying the **successor** activity
- **Forward pass** (computes ES/EF) · **backward pass** (computes LS/LF)
- ⭐ **Schedule compression:**

| | How | The cost |
|---|---|---|
| **Crashing** | Add resources/money to the critical path | **Increases cost** |
| **Fast tracking** | Run sequential activities in parallel | **Increases risk and rework** |

- **Resource leveling** (adjusts to resource limits — **can change the critical path**) vs. **resource smoothing** (adjusts within available float — **does not change the critical path**)
- **Monte Carlo simulation**, Gantt chart, milestone chart, **rolling wave planning**

**`6.1` Plan Resource Management** → resource management plan, ⭐ **team charter**, **RACI / RAM**
- RACI: **R**esponsible (does the work) · **A**ccountable (ultimately answerable — **exactly one person**) · **C**onsulted · **I**nformed

**`6.2` Estimate Resources** → resource requirements, **Resource Breakdown Structure (RBS)**

**Agile equivalents:** release planning · iteration planning · **velocity** · burndown chart

### Self-check

1. Given A(3) → B(5) → C(2), and A → D(4) → C: what is the critical path? What is D's total float?
2. Your sponsor demands two weeks cut with **no budget increase** → crashing or fast tracking? Why?

### What you must understand

**`4.2` Estimate Costs**
- Techniques: analogous · parametric · bottom-up · three-point · **cost of quality**

| | Covers | Who approves | Inside the cost baseline? |
|---|---|---|:--:|
| **Contingency reserve** | **Known unknowns** (identified risks) | **PM can use it directly** | ✅ Yes |
| **Management reserve** | **Unknown unknowns** (unforeseen risks) | Requires **management approval** | ❌ No |

**`4.3` Develop Budget → ⭐ Cost baseline**
- Cost aggregation → contingency → **cost baseline** → funding limit reconciliation → **S-curve**
- ⭐ **Budget = cost baseline + management reserve**

**⭐ EVM — the table you must know cold:**

| Symbol | Name | What it means in plain words |
|---|---|---|
| **PV** | Planned Value | By now, how much work *should* have been done, in money |
| **EV** | Earned Value | How much work has *actually* been done, in money |
| **AC** | Actual Cost | How much money has actually been spent |
| **BAC** | Budget at Completion | Total approved budget |

| Formula | Meaning | Good / Bad |
|---|---|---|
| **CV = EV − AC** | Cost variance | Negative = **over budget** |
| **SV = EV − PV** | Schedule variance | Negative = **behind schedule** |
| **CPI = EV / AC** | Cost performance index | < 1 = **over budget** |
| **SPI = EV / PV** | Schedule performance index | < 1 = **behind schedule** |
| **EAC = BAC / CPI** | Forecast (variance *will continue* — the default) | |
| **EAC = AC + (BAC − EV)** | Forecast (variance was *atypical*, won't recur) | |
| **EAC = AC + [(BAC − EV) / (CPI × SPI)]** | Forecast (must recover both cost and schedule) | |
| **ETC = EAC − AC** | How much more remains to be spent | |
| **VAC = BAC − EAC** | Final surplus or shortfall | Negative = **will exceed budget** |
| **TCPI = (BAC − EV) / (BAC − AC)** | Performance required on the remaining work | **> 1 = harder from here** |

**Memory aid:** everything starts with **EV**. Subtract (`−`) gives a **variance**; divide (`/`) gives an **index**. Compared against **AC** it's about **money**; against **PV** it's about **time**.

**Project selection metrics (business case):**
- Higher **NPV** = better · higher **IRR** = better · shorter **payback period** = better · **BCR > 1** = worth doing
- ⭐ **Sunk cost: IGNORE it in decisions.** "We've already sunk $2M so we must continue" → **always the wrong answer**.
- **Opportunity cost** = the value of the best alternative forgone

**`7.2` Identify Risks** → ⭐ **Risk register** (+ **risk report**)
- Techniques: SWOT · **assumption and constraint analysis** · **prompt lists** (PESTLE, TECOP) · root cause analysis · **Delphi technique** (anonymous experts, avoids groupthink) · checklists · interviews
- Who participates? **Everyone** — not just the PM.

**`7.3` Perform Risk Analysis**

| | Qualitative | Quantitative |
|---|---|---|
| Purpose | **Prioritize** which risks deserve attention | **Quantify** the impact numerically |
| Tools | Probability–impact matrix, urgency, ranking | ⭐ **EMV**, decision tree, **Monte Carlo**, **sensitivity/tornado diagram** |
| Always performed? | Yes | No — only on large or complex projects |

**`7.4` Plan Risk Responses → ⭐ memorize this table:**

| Threat | Opportunity | What it means |
|---|---|---|
| **Escalate** | **Escalate** | Outside project authority → raise it upward; **no longer tracked in the project risk register** |
| **Avoid** | **Exploit** | Drive probability to **0%** or **100%** |
| **Transfer** | **Share** | Move it to a third party (insurance, contract, joint venture) |
| **Mitigate** | **Enhance** | Reduce / increase probability or impact |
| **Accept** | **Accept** | Take no action — **active** (establish contingency reserve) or **passive** (do nothing) |

- **Residual risk** (what remains after the response) · **secondary risk** (created by the response itself)

### What you must understand

**⭐ XP (Extreme Programming) — practices to remember:**
- **Pair programming** (two people, one workstation) · **TDD** (write the test first) · **continuous integration** · **refactoring** · **simple design** · **collective code ownership** · **40-hour week / sustainable pace** · **on-site customer** · **metaphor** · **small releases**

**⭐ Lean — the seven wastes:** excess inventory · overproduction · waiting · unnecessary motion · transportation · over-processing · **defects**
- Principles: eliminate waste · amplify learning · decide as late as possible · deliver as fast as possible · empower the team · build quality in · see the whole

**⭐ Kanban — four identifying features:**
1. **Visualize** the workflow (kanban board)
2. ⭐ **Limit WIP (work in progress)** — this is the core mechanism
3. **Pull system** — take work when capacity frees up; don't push work down
4. **No mandatory sprints or timeboxes** — continuous flow

**Other methods — enough to recognize them:**
- **FDD** (Feature-Driven Development): five activities, organized around *features*
- **Crystal**: a family of methods, tailored to team size and criticality
- ⭐ **SAFe** (Scaled Agile Framework): scales agile across large organizations — **ARTs**, **PI Planning**
- **Disciplined Agile (DA)**: a toolkit owned by PMI — choose your way of working to fit the context

**⭐ Servant Leadership — central to PMI's worldview:**
- Leading by **serving the team**: removing impediments, creating the environment, growing people — not commanding.
- **The 12 principles of servant leadership** (listening, empathy, healing, awareness, persuasion, conceptualization, foresight, stewardship, commitment to the growth of people, building community…)
- **Tools:** coaching, mentoring, facilitation, removing **impediments**, shielding the team from outside noise
- ⭐ **The inverted pyramid:** in agile, the leader sits **underneath** supporting the team, not above issuing orders.

## Day 16 — Fri 28 Aug · Agile Product (2/2): Metrics & Hybrid

**Study:** Section 10, lectures 19–41 (*Prioritization Techniques* → *Section Quiz*)

### What you must understand

**⭐ Prioritization techniques:**

| Name | How it works |
|---|---|
| **MoSCoW** | **M**ust have · **S**hould have · **C**ould have · **W**on't have |
| **Kano model** | Basic (expected) · Performance (more is better) · Delighter (unexpected pleasure) |
| **WSJF** | Weighted Shortest Job First = cost of delay ÷ job size |
| **100-point method** | Each person distributes 100 points across items |
| **Paired comparison** | Compare items two at a time |
| **MVP-based** | Prioritize by the minimum needed to learn |

**⭐ Flow metrics:**
- **Lead time** = from **customer request** to **delivery** · **cycle time** = from **work starting** to **finishing**. Lead time contains cycle time.
- ⭐ **Little's Law:** `WIP = throughput × cycle time` → **to deliver faster, reduce WIP.** This is the mathematical basis of Kanban.
- **Agile KPIs:** velocity, throughput, escaped defects, lead/cycle time, customer satisfaction.
- ⭐ **Cumulative Flow Diagram (CFD):** whichever band **widens** marks the bottleneck.
- ⭐ **Burndown** (how much remains — hides added scope) vs. **burnup** (how much is done, plus a total-scope line — **shows scope change**).
- **Variance and trend analysis** in an agile context.

**Other concepts:**
- ⭐ **Technical debt:** debt incurred by shortcuts — the interest is paid in declining speed. It must enter the backlog to be repaid.
- **Timebox** · ⭐ **Spike** (a short timebox for **learning or research**, producing no feature — *architectural spike* / *risk-based spike*)
- **Risk in agile:** the **risk-adjusted backlog** (high-risk items done early), **risk burndown chart**, risks treated as backlog items.
- **Agile contracting:** graduated fixed price · fixed-price work packages · ⭐ **"money for nothing and change for free"** (the customer may swap requirements at no cost provided total size is unchanged, and may terminate early paying only for work not yet done)
- **CAS (Complex Adaptive Systems).**
- ⭐ **The Cynefin framework** — choose your action by context:

| Domain | Characteristic | Action |
|---|---|---|
| **Clear/Simple** | Cause and effect obvious | Sense → Categorize → Respond (best practice) |
| **Complicated** | Requires expertise | Sense → Analyze → Respond (good practice) |
| **Complex** | Only understandable after acting | **Probe → Sense → Respond** (emergent — **agile's home**) |
| **Chaotic** | Turbulent | Act → Sense → Respond (novel) |
| **Disorder** | You don't yet know where you are | Break it down until you can classify it |

- ⭐ **Stacey matrix:** requirements certainty × technology certainty → from simple (predictive) through to anarchy (agile/chaos).
- **Value stream mapping** and **Kaizen** (continuous improvement in small steps).
- ⭐ **Pre-mortem:** before starting, imagine the project **has already failed** and ask why — a very powerful risk identification technique.
- **Retrospective:** review how the team works and select **one or two improvements** for the next sprint (not a list of twenty).

**⭐ Hybrid projects and methods** — an ECO 2026 focus:
- When hybrid fits: part of the requirements are clear (predictive) and part are uncertain (agile); the organization is mid-transition; regulation demands documentation while the product needs iteration.
- Examples: predictive infrastructure/construction plus agile software; or predictive at the program level with agile at the team level.

## Day 20 — Wed 2 Sep · **PMP Exam Mindset** — the highest-scoring day

**Study:** the course section *PMP Exam Mindset*

> **This is the most valuable day in scoring terms.** Knowledge lets you understand the question; **mindset makes you pick the right answer.** Plenty of people who know enough still fail because they answer according to *how their company works* rather than *how PMI wants*.

### The PMI mindset — core rules

1. **The PM is always proactive, never reactive.** They anticipated it; they have a plan.
2. **Understand the problem before acting.** Gather information → analyze the root cause → then respond.
3. **Don't escalate early.** Escalate only when it genuinely exceeds your authority.
4. **Don't blame; don't avoid.** The PM owns it.
5. **Servant leadership.** The team self-organizes and decides *how*. The PM removes obstacles rather than issuing orders.
6. **Every change goes through change control.** No exceptions, including verbal sponsor requests.
7. **No gold plating.** Never deliver beyond scope, even for free.
8. **Direct communication first.** A problem with one person → talk to that person first.
9. **Never violate** ethics, law, contract, or safety — regardless of pressure.
10. **Priority when things conflict:** `Safety/Ethics > Legal compliance > Customer value > Quality > Schedule/Cost`

### Question-reading strategy

**Step 1 — establish the context before reading the options:**
- Predictive or agile/hybrid? (keywords: sprint, backlog, PO, iteration → agile)
- Which process group are you in?
- Whose problem is it? What authority does the PM have here?

**Step 2 — watch the directional keywords:**
- **"FIRST"** / **"NEXT"** → the **smallest, nearest** action — usually *find out more* or *have a conversation*
- **"BEST"** → the most correct long-term solution
- **"MOST likely cause"** → root cause analysis
- **"Should have done"** → asks about prevention; the answer usually lives in **planning**

**Step 3 — eliminate.** These options are nearly always WRONG:

| An option that says | Why it's wrong |
|---|---|
| "Escalate immediately to the sponsor/manager" | The PM hasn't tried to handle it |
| "Ignore it / do nothing" | The PM is never passive |
| "Decide on the team's behalf" | Violates empowerment |
| "Implement the change and report later" | Bypasses change control |
| "Work overtime / add people to catch up" | Doesn't address the root cause |
| "Replace the team member" | Far too heavy as a first step |
| "Refuse outright because it's out of scope" | No impact assessment performed |
| "Conceal it / compromise on ethics" | Violates the Code of Ethics |

**Step 4 — for agile items:** ask the team · raise it in the retrospective · let the PO prioritize · stay transparent with stakeholders.

### ⭐ Pinned formula sheet — reproduce it from memory

**EVM**
```
CV  = EV − AC              (negative = over budget)
SV  = EV − PV              (negative = behind schedule)
CPI = EV / AC              (<1 = over budget)
SPI = EV / PV              (<1 = behind schedule)
EAC = BAC / CPI            (variance will continue — the default)
EAC = AC + (BAC − EV)      (atypical variance, won't recur)
EAC = AC + [(BAC − EV) / (CPI × SPI)]
ETC = EAC − AC
VAC = BAC − EAC            (negative = will exceed budget)
TCPI = (BAC − EV) / (BAC − AC)    (>1 = harder from here)
```

**Schedule**
```
PERT (beta)   = (O + 4M + P) / 6
Triangular    = (O + M + P) / 3
Std deviation = (P − O) / 6
Total float   = LS − ES = LF − EF
Critical path = the LONGEST path, float = 0
```
